
为了将特定的通用模板表达为**具名的概念**（named concepts），我们需要构造一种**可以接收其他函数作为参数**或**可以把函数当作返回值**的函数。这种可以操作函数的函数就叫做**高阶函数**（higher-order functions）。

---

## 1.6.1 函数作为参数


思考以下三个计算**求和**的函数。

第一个函数 `sum_naturals` 会计算从 1 到 n 的自然数之和：

```python
>>> def sum_naturals(n):
        total, k = 0, 1
        while k <= n:
            total, k = total + k, k + 1
        return total

>>> sum_naturals(100)
5050
```

第二个函数 `sum_cubes` 函数会计算 1 到 n 的自然数的立方之和。

```python
>>> def sum_cubes(n):
        total, k = 0, 1
        while k <= n:
            total, k = total + k*k*k, k + 1
        return total

>>> sum_cubes(100)
25502500
```

第三个函数 `pi_sum` 会计算下列各项的总和，它的值会非常缓慢地收敛到 Π。

$$\frac{8}{1*3} + \frac{8}{5*7} + \frac{8}{9*11} + ...$$
```python
>>> def pi_sum(n):
        total, k = 0, 1
        while k <= n:
            total, k = total + 8 / ((4*k-3) * (4*k-1)), k + 1
        return total

>>> pi_sum(100)
3.1365926848388144
```

这三个函数明显有着共同的**底层模式**。它们几乎完全一样，唯一的区别在于函数名，以及用来计算每一项的那个关于 `k` 的表达式。

我们其实可以通过填充同一个模板的**槽位**来生成这些函数：

```python
def <name>(n,term):
    total, k = 0, 1
    while k <= n:
        total, k = total + <term>(k), k + 1
    return total
```

例：
```python
def summation(n,term):
    total, k = 0, 1
    while k <= n:
        total, k = total + cube(k), k + 1
    return total
    
def cube(x):
    return x*x*x

def sum_cubes(n):
    return summation(n,cube)
    
result = sum_cubes(3)
```

```python
>>> def summation(n, term):
        total, k = 0, 1
        while k <= n:
            total, k = total + term(k), k + 1
        return total
>>> def identity(x):
        return x
>>> def sum_naturals(n):
        return summation(n, identity)
>>> sum_naturals(10)
55
```

`summation` 也可以直接被调用，而无需为特定的序列去定义另一个函数。

```python
>>> summation(10, square)
385
```

## 1.6.2 函数做为通用方法

**把“求解过程”抽象成一个通用函数（算法骨架），再把“具体问题的细节”当作参数（函数）传进去**。所以它叫“函数作为通用方法”。

下面的例子，它实现了一种通用的**迭代改进**（iterative improvement）算法，并使用它来计算黄金分割率。[黄金分割率](http://www.geom.uiuc.edu/~demo5337/s97b/art.htm) 通常被称为“phi”，是一个接近 1.6 的数字。

### 1) `improve` 是一个“迭代改进”的通用模板

```python
def improve(update, close, guess=1):
    while not close(guess):
        guess = update(guess)
    return guess

```

- `guess`：当前猜测值（初始值默认 1）
    
- `update(guess)`：给你一个“更好的猜测”（一次迭代规则）
    
- `close(guess)`：判断“现在够不够接近答案了”（停止条件）
    
- 循环：不够近就继续更新，直到够近为止

==关键点==：`improve` **完全不知道**你要求什么（求根？求极值？求不动点？），它只负责“不断迭代直到满足停止条件”这个通用流程。

### 2) 黄金分割率例子：把“问题细节”塞进 `update` 和 `close`

黄金分割率 φ 有一个经典性质：

$$\varphi = 1 + \frac{1}{\varphi} \quad\Longleftrightarrow\quad \varphi^2 = \varphi + 1$$

他们用这个性质构造了：

#### (1) 更新规则 `golden_update`

```python
def golden_update(guess):
    return 1/guess + 1

```

这正是在做：  
如果真正的答案满足 x=1+1/x，那就用

$$x_{new} = 1 + \frac{1}{x_{old}}$$​

不断迭代，期望收敛到那个满足方程的值（这叫**不动点迭代**）。

#### (2) 停止条件 `square_close_to_successor`

```python
def square_close_to_successor(guess):
    return approx_eq(guess * guess, guess + 1)

```

因为答案满足 x2=x+1x^2 = x + 1x2=x+1，所以当 `guess*guess` 和 `guess+1` 足够接近时，就认为已经找到 φ 了。

#### (3) `approx_eq`

```python
def approx_eq(x, y, tolerance=1e-15):
    return abs(x - y) < tolerance

```

浮点数算不出“完全相等”，只能用“误差小于某个阈值”当作相等。

### 3) 为什么说这里体现了“高阶函数/闭包”的思维

以 `golden_update` 和 `square_close_to_successor` 为参数来调用 `improve` 将计算出黄金分割率的一个有限近似值。

```python
improve(golden_update, square_close_to_successor)
```

- 用 `improve` 这个通用迭代框架，  
- 但具体怎么“改进”用 `golden_update`，  
- 判断“够不够好”用 `square_close_to_successor`。

`improve` 里会反复调用你传进去的这两个函数。  
而且它们会跟 `guess` 一起在 `improve` 的局部环境里配合工作——这就是你看到的“把函数当参数传递/绑定”的意思

### 4) 最后的测试在干嘛

他们用黄金分割率的闭式解：

$$\varphi = \frac{1 + \sqrt{5}}{2}$$​​

算出“真值” `phi`，再检查 `improve(...)` 得到的 `approx_phi` 是否足够接近；`assert` 通过就说明实现靠谱。

```python
>>> from math import sqrt
>>> phi = 1/2 + sqrt(5)/2
>>> def improve_test():
        approx_phi = improve(golden_update, square_close_to_successor)
        assert approx_eq(phi, approx_phi), 'phi differs from its approximation'
>>> improve_test()
```


缺点：
1. 全局环境中塞满了各种小函数的名字（全局帧混乱），而且这些名字都必须全局唯一；
2. 我们还受到特定函数签名的限制：`improve` 的 `update` 参数只能接受一个参数。

### 1.6.3 定义函数 III ：嵌套定义

**嵌套函数定义**（Nested function definition）可以同时解决上述两个问题，但需要我们进一步丰富环境模型。

现在考虑一个新问题：求一个数的平方根（在编程语言中常简写为 `sqrt`）。反复应用下面的更新规则，可以收敛到 a 的平方根：

```python
>>> def average(x, y):
        return (x + y)/2

>>> def sqrt_update(x, a):
        return average(x, a/x)
```

#### 理解：

##### 1) 先抓住关键直觉：如果 x 是 $\sqrt a$的近似

- 那么$x^2$ 应该接近 a。
    
- 同时，$\frac{a}{x}$也会接近 $\sqrt a$（因为如果 x≈$\sqrt a$​，两边除以 x 得 $\frac{a}{x}\approx \sqrt a$​）。

更妙的是：  
当 x 偏大时，$\frac{a}{x}$会偏小；当 x 偏小时，$\frac{a}{x}$​ 会偏大。  
所以 **x 和 $\frac{a}{x}$​** 往往分别在真值 $\sqrt a$​ 的两侧。

##### 2) 更新规则为什么是取平均


既然 x 和 a/x 往往一大一小、夹着 $\sqrt a$​，那最自然的“改进”就是取它们的平均：

$$x_{\text{new}}=\frac{x+\frac{a}{x}}{2}$$​​

这一步会把猜测**拉回到中间**，通常会比原来的 x 更接近 $\sqrt a​$。

---

但这个需要两个参数的 `sqrt_update` 无法直接传给 `improve`（因为 `improve` 要求 `update` 只接受一个参数）。


更好的办法是把函数定义放在另一个函数的内部：
```python
>>> def sqrt(a):
        def sqrt_update(x):
            return average(x, a/x)
        def sqrt_close(x):
            return approx_eq(x * x, a)
        return improve(sqrt_update, sqrt_close)
```
